# 두 번째 데이터셋에서 카드 이력 효과 확인

[Fraud Detection Handbook](https://fraud-detection-handbook.github.io/fraud-detection-handbook/Chapter_3_GettingStarted/SimulatedDataset.html)의 공식 시뮬레이터로 자료를 생성했습니다. 공식 노트북 커밋과 파일 해시는 [매니페스트](../data/manifests/handbook_benchmark.json)에 기록했습니다. 노트북과 생성된 거래 파일은 로컬의 `data/raw/handbook/`에 보관합니다.

## 실험 조건

- 2018년 4~6월로 학습하고, 7월은 검증, 8~9월은 최종 테스트에 사용했습니다.
- 두 XGBoost의 트리 깊이 7, 트리 100개, 학습률 0.1, 시드 42를 고정했습니다. 두 모델 모두 이번 거래의 금액과 시간대를 사용합니다. 업종 정보가 없어 이번 비교에서는 사용하지 않았습니다.
- 이력을 추가한 모델에는 최근 1시간·7일 거래 건수, 최근 7일 평균 금액과 표준편차를 더했습니다. 이 데이터의 고객 ID를 기존 카드 이력의 키로 사용했습니다. 카드 이력은 거래가 발생한 순서대로 계산하며 동일 시각에는 원본 행 순서를 사용합니다.
- 거래 ID는 같은 점수와 시각에서 순서를 정하는 데 사용합니다. 고객 ID와 사기 시나리오 번호는 모델 입력에서 제외했습니다. 사기 라벨은 학습과 평가에 사용합니다.
- 매일 각 모델의 점수 상위 20건을 조사 대상으로 삼았습니다. 고정 점수로 평가할 때는 기존 비용 가정으로 검증 기간에서 기준을 고른 뒤 최종 테스트에 적용했습니다.

## 거래 분포

공식 시뮬레이터에서 거래 1,754,155건과 사기 라벨 14,681건(0.84%)을 재현했습니다. 금액이 0인 정상 거래 42건은 FinGuard의 양수 금액 규칙에 따라 두 비교 모델에서 동일하게 제외했습니다.

| 구간 | 전체 거래 | 사기 |
| --- | ---: | ---: |
| 학습 | 872,776 | 6,845 |
| 검증 | 296,918 | 2,620 |
| 최종 테스트 | 584,419 | 5,216 |

## 결과

| 데이터·조건 | 찾은 사기 | 조사 대상 중 사기 | 전체 사기 중 발견 | AP |
| --- | ---: | ---: | ---: | ---: |
| Handbook, 이력 없음 | 608 | 49.84% | 11.66% | 0.1315 |
| **Handbook, 이력 포함** | **1,063** | **87.13%** | **20.38%** | **0.2999** |
| Sparkov, 이력 없음 | 1,561 | 42.42% | 77.58% | 0.7729 |
| Sparkov, 이력 포함 | 1,691 | 45.95% | 84.05% | 0.8781 |

하루 20건으로 Handbook에서 총 1,220건을 조사했습니다. 이력을 넣자 같은 조사 건수에서 사기 455건을 더 찾았습니다. 이 기간의 사기 5,216건 중 1,220건을 모두 사기로 골라도 재현율의 상한은 23.39%입니다. 한도를 하루 50건으로 늘리면 사기 탐지는 이력 없이 1,188건, 이력을 넣으면 1,561건이었습니다.

검증에서 비용 기준으로 고른 고정 점수를 테스트에 적용하면, 조사 건수는 이력 없이 2,380건, 이력 포함 3,393건입니다. 이때 찾은 사기는 1,182건에서 1,643건으로 늘었고, 정밀도는 49.66%에서 48.42%로 내려갔습니다. 고정 점수 결과에는 서로 다른 조사 건수가 반영됩니다.

Sparkov 값은 [기존 실험](history_tuning.md)의 깊이 5 비교에서 가져왔습니다. 각 데이터에서 XGBoost 설정을 고정해 이력 추가의 효과를 측정했으며, 모델은 데이터셋별로 다시 학습했습니다. 두 합성 데이터의 사기 생성 규칙과 입력 항목이 다르므로 데이터 간 절대 성능보다 각 데이터 내 개선폭을 비교합니다.

## 재현 방법

```sh
uv run --no-project --python 3.12 --with numpy==1.26.4 --with pandas==2.2.3 python tools/generate_handbook_data.py
uv run --locked --group ml python tools/benchmark_handbook.py
```

첫 명령은 검토한 공식 노트북의 생성·라벨링 코드만 실행하고 CSV를 만듭니다. 두 번째 명령은 CSV 해시를 확인한 뒤 비교를 실행하고 `artifacts/handbook_benchmark/results.json`에 검증·테스트 지표를 저장합니다. 세 기간과 XGBoost 설정은 [벤치마크 설정](../configs/handbook_benchmark.toml)에 있습니다.
