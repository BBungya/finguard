# FinGuard 거래 탐지 모델 카드

## 용도와 입력

카드 거래에 위험 점수를 매겨 담당자의 조사 순서를 정하는 데 사용합니다. 모델 입력은 현재 결제의 금액·시간대·가맹점 업종과, 선택한 모델에 따라 같은 카드의 직전 1시간·7일 거래 건수 및 최근 7일 평균 금액·표준편차입니다. 카드 ID는 이력 조회 키로 사용합니다. 현재 거래와 이후 거래는 해당 거래의 이력 계산에 들어가지 않습니다. [이력 피처 정의](history_features.md)

## 학습과 평가

[Sparkov v1](../data/manifests/sparkov_evaluation.json)의 2019년 거래 924,850건으로 학습했습니다. 2020년 상반기 401,883건에서 모델과 점수 기준을 골랐고, 하반기 525,661건에서 평가했습니다. 모델 선택 기준은 하루 20건으로 찾은 사기 건수이며, 동률이면 AP를 비교합니다. 고정 점수 기준은 상반기에서 별도로 비용을 최소화하는 값으로 선택합니다. [평가 명세](ml_evaluation.md)

## 선택한 모델

**카드 이력을 넣은 XGBoost, 깊이 7, 트리 100개, 학습률 0.1**을 #9 거래 점수 API의 초기 후보로 선택했습니다. 같은 깊이와 트리 수에서 학습률 0.2의 검증 AP는 0.9442로 0.1의 0.9429보다 높았습니다. 하루 20건으로 찾은 사기는 0.1의 2,056건과 0.2의 2,050건이어서, 사전에 정한 조사 한도 기준에 따라 0.1을 골랐습니다. 0.2 결과는 상반기 검증 수치입니다.

하반기에는 하루 20건으로 사기 1,711건을 발견했습니다. 조사 대상의 46.49%, 전체 사기 2,012건의 85.04%입니다. 일일 상위 20건은 당일 점수를 모아 순위를 매깁니다. 고정 점수 평가는 검증에서 고른 `0.07275895774364471` 이상인 거래를 모두 조사 대상으로 봅니다. 하반기에 이 기준을 적용하면 3,042건을 조사해 사기 1,822건을 찾았습니다. 점수는 조사 후보의 우선순위에 사용하며 최종 판단은 담당자가 합니다.

## 오류 집계와 비용 측정 방법

- 일별 전체 거래에서 점수 상위 20건을 고른 뒤, 시간대·금액대·학습 시 등장 여부로 나눠 놓친 사기와 조사 대상으로 고른 정상 거래를 셉니다. 시간대는 원본 결제 시각을 6시간 간격으로 나눴고, 금액대는 원본 단위로 50·200·500에서 나눴습니다.
- 보정 수준은 0~1 점수를 고정 구간으로 나눠 평균 점수와 실제 사기 비율을 대조합니다. Brier 점수는 개별 예측과 실제 라벨의 제곱 오차 평균이고, ECE는 구간별 차이의 거래 수 가중평균입니다. 두 값 모두 작을수록 해당 방식으로 측정한 차이가 작습니다.
- 추론 시간은 최종 테스트에서 고르게 고른 200건의 전처리된 입력으로 측정합니다. 워밍업 후 모델에 한 건씩 보내고, 단일 스레드에서 중앙값과 95백분위 시간을 잽니다. 모델 파일 크기는 압축하지 않은 저장 크기입니다. 이력 조회·전처리·네트워크 시간을 포함한 API 지연은 #9 이후에 측정합니다.

## 오류가 집중된 구간

선택한 모델이 하루 상위 20건으로 내보낸 거래와 놓친 거래를 집계했습니다. 아래 세 구분은 같은 거래를 각각 다른 기준으로 나눈 것이므로 서로 더하지 않습니다.

| 기준 | 구간 | 찾은 사기 | 조사한 정상 | 놓친 사기 |
| --- | --- | ---: | ---: | ---: |
| 시간대 | 00~05시 | 635 | 501 | 69 |
| 시간대 | 06~11시 | 59 | 181 | 19 |
| 시간대 | 12~17시 | 52 | 408 | 46 |
| 시간대 | 18~23시 | 965 | 879 | 167 |
| 금액대 | 50 미만 | 301 | 781 | 135 |
| 금액대 | 50 이상~200 미만 | 32 | 124 | 37 |
| 금액대 | 200 이상~500 미만 | 511 | 156 | 27 |
| 금액대 | 500 이상 | 867 | 908 | 102 |
| 카드 | 학습 구간에 등장 | 1,571 | 1,969 | 290 |
| 카드 | 학습 구간에 미등장 | 140 | 0 | 11 |

18~23시는 놓친 사기 건수가 가장 많았고, 12~17시는 사기 98건 중 52건만 찾아 시간대별 재현율이 가장 낮았습니다. 금액 50 이상~200 미만에서도 사기 69건 중 32건을 찾았습니다. 학습 구간에 없던 카드의 테스트 거래는 151건 모두 사기였으므로 이 그룹의 정상 거래 판정 성능은 확인할 수 없습니다.

## 보정 수준과 모델 비용

| 후보 | 하반기 하루 20건으로 찾은 사기 | Brier | ECE | 트리 / 노드 | 모델 크기 | 한 건 중앙값 / p95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 랜덤포레스트 + 이력, 깊이 10 | 1,592 | 0.001601 | 0.002483 | 40 / 16,638 | 1,348,505 B | 2.41 / 3.61 ms |
| XGBoost + 이력, 깊이 5 | 1,691 | 0.001022 | 0.000265 | 100 / 4,704 | 235,666 B | 1.95 / 2.91 ms |
| **XGBoost + 이력, 깊이 7** | **1,711** | **0.000927** | **0.000166** | 100 / 11,232 | 457,669 B | 1.91 / 3.18 ms |

깊이 7 모델이 깊이 5보다 같은 조사량에서 사기 20건을 더 찾았고, 노드 수는 약 2.4배였습니다. 점수 0.2 이상~0.5 미만인 거래 521건에서 평균 점수는 31.13%, 실제 사기 비율은 29.17%였습니다. 전체 ECE는 정상 거래가 대부분인 낮은 점수 구간의 영향을 받습니다. 이 결과는 기존 Sparkov 합성 데이터로 측정한 것이므로 서비스에서는 점수를 **위험 점수**로 표시합니다.

시간은 Windows 11, 논리 CPU 8개 환경의 로컬 실행에서 측정했습니다. Python 3.12.13, NumPy 2.5.5, pandas 3.1.1, scikit-learn 1.9.1, XGBoost 3.4.1을 사용했습니다.

## 재현

```sh
uv run --locked --group ml python tools/tune_history_models.py
```

기본 난수 시드는 42입니다. [기준 설정](../configs/baseline.toml)과 [후보 설정](../configs/history_tuning.toml)을 사용합니다. 버전, 기준 점수, 비용 가정에 따른 결과, 오류 세부 집계는 로컬 `artifacts/history_tuning/results.json`에서 확인할 수 있습니다. 선택 모델은 `selected_model.joblib`, 기본 거래 전처리기는 `preprocessor.joblib`에 저장합니다. 모델 입력에는 기본 전처리 결과 뒤에 최근 1시간 건수, 7일 건수, 7일 평균 금액, 7일 표준편차를 순서대로 붙입니다.
