# 카드 거래 이력 피처

피처는 거래를 평가할 때 모델에 전달할 값입니다. 같은 카드로 10시에 10, 10시 20분에 30을 결제했다면, 10시 30분 거래를 처리하기 직전 최근 1시간 결제는 2건이고 평균은 20입니다. 현재 거래는 계산이 끝난 뒤 카드 이력에 추가합니다.

## 피처 사전

| 이름 | 뜻 |
| --- | --- |
| `transaction_id` | 피처가 계산된 거래 ID |
| `feature_version` | 계산 규칙 버전. 현재 `1` |
| `count_1h` | 직전 1시간 동안 처리한 같은 카드의 거래 수 |
| `count_7d` | 직전 7일 동안 처리한 같은 카드의 거래 수 |
| `mean_amount_7d` | 직전 7일 거래 금액의 평균. 이력이 없으면 `None` |
| `std_amount_7d` | 직전 7일 거래 금액의 모집단 표준편차. 이력이 없으면 `None` |

시각·금액은 [거래 검증 규칙](transaction_replay.md)을 따릅니다. 카드 ID를 이력 조회 키로 사용하며, 동일 카드의 금액은 같은 단위로 제공되어야 합니다. 사기 라벨은 피처 계산에 사용하지 않습니다. 금액 통계는 십진수 유효 숫자 28자리 기준입니다.

## 경계 조건 비교

| 상황 | 가능한 처리와 결과 차이 | 버전 1에서 선택한 규칙 |
| --- | --- | --- |
| 첫 거래 또는 7일 이력 없음 | 평균과 표준편차에 0을 넣으면 값이 항상 숫자가 됩니다. 비워두면 실제로 변동이 0인 경우와 구분할 수 있습니다. | 건수는 0, 평균과 표준편차는 `None`. 학습용 값 채우기는 피처 계산과 분리합니다. |
| 직전 거래가 1건 | 금액이 10이면 모집단 표준편차는 0이고 표본 표준편차는 정의되지 않습니다. 직전 금액이 10과 30이면 각각 10과 약 14.14입니다. | 정해진 기간의 관측 거래 전체를 요약하므로 모집단 표준편차를 씁니다. |
| 정확히 1시간 또는 7일 전 | 경계를 포함하면 바로 그 시각의 거래도 집계됩니다. 경계를 제외하면 해당 거래가 1초 이른 거래와 똑같이 빠집니다. | 정확히 경계에 있는 거래까지 포함하고, 경계를 넘기면 제외합니다. |
| 같은 시각에 들어온 2건 | 같은 시각의 거래를 모두 제외하면 두 건이 동일한 직전 이력을 봅니다. 처리 순서를 반영하면 두 번째 건은 먼저 처리한 거래까지 봅니다. | #3의 CSV 순서를 사용합니다. 한 건 처리에서도 호출 순서를 따릅니다. |
| 필수 값 누락·오류 | 금액을 0으로 채우면 건수와 평균이 달라집니다. 잘못된 행을 제외하면 통계에는 검증에 통과한 거래가 반영됩니다. | #3에서 제외합니다. 계산기에 직접 들어온 빈 카드 ID나 잘못된 금액도 오류로 처리합니다. |
| 이미 처리한 거래보다 이른 거래 도착 | 과거에 끼워 넣으면 이후에 계산한 피처도 다시 계산해야 합니다. 오류로 처리하면 기존 이력을 그대로 사용할 수 있습니다. | CSV는 #3에서 시간순으로 정렬합니다. 한 건 처리에서 같은 카드의 시각이 역전되면 오류를 반환합니다. |

예를 들어 10시 거래를 계산할 때, 같은 카드에 8시 59분 59초와 9시 정각 거래가 각각 한 건 있다면 1시간 건수는 경계를 포함할 때 1건, 제외할 때 0건입니다. 10시 거래가 두 건이면 이 규칙에서 첫 번째 건의 직전 이력은 1건, 두 번째 건은 2건입니다. 두 번째 건에서도 동시각 거래를 제외하는 규칙을 썼다면 1건입니다.

## 실행 및 검증

학습용 일괄 계산은 `compute_history_features(load_transactions(path).transactions)`로 실행합니다. 한 건 처리는 `HistoryFeatureCalculator.process(transaction)`를 호출합니다. 두 방식에 검증 및 중복 제거를 마친 거래를 카드별로 같은 순서로 전달해야 결과가 일치합니다. 현재 한 건 처리는 메모리에서 실행하며, API의 중복 요청과 동시 처리 정책은 [#9](https://github.com/BBungya/finguard/issues/9)에서 다룹니다.

```sh
uv run --locked pytest -q tests/test_features.py
```

테스트에서 신규 카드, 1건 이력, 1시간·7일 경계, 같은 시각, 잘못된 값과 늦게 도착한 거래를 확인합니다. 동일 거래열을 일괄 및 한 건씩 처리해 출력이 정확히 같은지 비교합니다. 이후 거래의 금액을 변경해도 그 전 거래의 값과 변경 대상 거래 자체의 직전 이력이 유지되는지 확인합니다.

교육용 샘플 998건에서도 일괄 처리와 한 건 처리 결과가 모두 일치했습니다. 각 거래의 직전 이력을 직접 찾아 계산한 결과와 비교했을 때 건수는 정확히 일치했고, 평균과 표준편차의 절대 오차는 `1e-20` 미만이었습니다.
