# CSV 거래 검증과 시간순 재생

재생은 파일에 저장된 과거 거래를 발생한 순서대로 한 건씩 꺼내는 것을 뜻합니다. 예를 들어 10시 결제와 10시 5분 결제가 있으면, 파일에서 순서가 뒤바뀌어도 10시 결제가 먼저 나옵니다. 지금은 로컬 터미널의 표준 출력으로 내보냅니다. [거래 점수 API 이슈 #9](https://github.com/BBungya/finguard/issues/9)에서 같은 거래 흐름을 API에 연결합니다.

## 입력과 실행

UTF-8 CSV를 사용합니다. 교육용 파일의 컬럼 이름을 사용하며, 출처와 사용 범위는 [데이터 카드](data_card.md)에 있습니다.

| CSV 컬럼 | 검증 규칙 |
| --- | --- |
| `trans_num`, `cc_num` | 비어 있지 않은 거래 ID와 카드 ID. 문자열로 읽어 앞자리 0을 보존합니다. |
| `trans_date_trans_time` | 유효한 날짜와 초 단위 시각. 날짜와 시각 사이는 공백 또는 `T`를 허용합니다. 원본 시각에 시간대를 붙이지 않습니다. |
| `amt` | 0보다 큰 금액. 소수점 아래 최대 두 자리이며 십진수로 정확히 읽습니다. 통화는 데이터 출처에 따릅니다. |
| `category` | 비어 있지 않은 거래 업종 |
| `is_fraud` | 선택 컬럼. 0은 정상, 1은 사기, 값이 없으면 미분류입니다. 평가용 라벨입니다. |

```sh
uv run --locked python -m finguard.replay data/raw/transactions.csv --speed 0
```

`--speed 0`은 기다리지 않고 출력합니다. `--speed 1`은 기록된 거래 사이의 간격만큼 기다리고, `--speed 2`는 간격을 절반으로 줄입니다.

## 순서와 예외 처리

- 먼저 CSV 전체를 검증합니다. 같은 거래 ID가 여러 번 나오면 검증을 통과한 첫 행을 사용합니다. 나머지 행은 파일 줄 번호와 실패 이유를 남깁니다.
- 파일에서 이미 읽은 거래보다 이른 시각의 거래가 뒤에 나오면 순서가 뒤바뀐 건으로 집계하고, 정렬할 때 원래 발생 시각의 위치에 넣습니다. 발생 시각이 같은 거래는 파일에 나온 순서를 유지합니다. 운영 API에 뒤늦게 도착한 거래 정책은 #9에서 정합니다.
- 거래는 표준 출력에 줄마다 JSON 하나로 나오고, 입력 건수·제외 건수·이유·재생 속도는 표준 오류에 요약됩니다. 정상적으로 읽은 파일은 일부 행을 건너뛰어도 종료 코드 0을 반환합니다. 파일을 열 수 없거나 헤더 또는 CSV 구문에 문제가 있으면 종료 코드 2를 반환합니다.
- 출력에는 입력에 들어 있는 거래 ID와 카드 ID가 포함됩니다. 외부 데이터를 로컬에서 재생한 출력은 로컬에 보관하고 공개 시연에는 합성 ID를 사용합니다.

## 검증 결과

[교육용 샘플](data_card.md)은 998건 모두를 즉시 출력했습니다. 제외 건수와 순서가 뒤바뀐 건수는 각각 0건이었습니다. 동일 파일과 설정으로 두 번 실행해 전체 출력 순서가 일치하는지 확인했습니다. 합성 입력으로 동시각, 잘못된 행, 중복과 순서가 뒤바뀐 행을 테스트합니다.
