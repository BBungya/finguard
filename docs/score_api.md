# 로컬 거래 점수 API

이슈 #9의 거래 점수 API입니다. #8에서 저장한 전처리기·군집 모델·XGBoost와 기존 이력 계산을 사용합니다. 모델은 시작 시 한 번 읽습니다. 거래와 결과를 DB에 남기는 방법은 [PostgreSQL 실행 안내](postgresql.md)에 있습니다.

## 시작하기

저장소 루트에서 실행합니다. 모델 경로의 기본값은 `artifacts/behavior_ablation/selected_model.joblib`입니다. 이 파일은 로컬에서 학습한 결과이며, 다시 만들려면 다음 첫 번째 학습 명령을 실행합니다.

```powershell
uv run --locked --group ml python tools/compare_behavior_features.py
uv run --locked --group api uvicorn finguard.api:app --host 127.0.0.1 --port 8000 --workers 1
```

위 명령은 `DATABASE_URL`이 없으면 메모리 모드로 동작합니다. 모델 파일 경로를 바꾸려면 서버 실행 전에 PowerShell에서 `$env:SCORING_MODEL_PATH = '파일 경로'`를 지정합니다. `.env`를 읽으려면 `uv run --env-file .env`를 사용합니다.

브라우저에서 `http://127.0.0.1:8000/docs`를 열면 입력 양식에서 직접 거래를 보낼 수 있습니다. 별도 터미널에서는 다음 명령을 사용합니다.

```powershell
$body = @{
    transaction_id = 'demo_tx_001'
    card_id = 'demo_card_001'
    occurred_at = '2026-11-19T10:30:00'
    amount = '100.00'
    category = 'shopping_net'
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/transactions/score' -ContentType 'application/json' -Body $body
```

## 요청과 응답

`POST /transactions/score`는 거래 ID, 카드 ID, 결제 시각, 금액, 업종을 받습니다. ID와 업종은 비어 있지 않은 문자열이어야 합니다. 금액은 양수이며 소수점 아래 두 자리까지 문자열로 보냅니다. 시각은 초 단위의 시간대 없는 원본 시각입니다. 데이터의 통화와 시각 기준을 일관되게 사용합니다. 알 수 없는 업종은 학습 때 정의한 전처리기의 처리 규칙을 따릅니다.

| 응답 | 의미 |
| --- | --- |
| `transaction_id` | 요청한 거래 ID |
| `risk_score` | 0~1 범위의 모델 위험 점수 |
| `review_required` | 저장된 고정 점수 기준 이상인지 |
| `threshold` | 사용한 고정 점수 기준. 기준이 없으면 모든 거래의 조사 여부가 false |
| `cluster_id` | 결제 직전 행동 그룹. -1은 최근 이력 없음 |
| `model_version` | 읽은 모델 파일의 SHA-256 |
| `policy_version` | 고정 점수 판단 규칙 버전 |
| `features` | 최근 1시간·7일 거래 건수, 최근 7일 평균·표준편차, 피처 버전 |

첫 거래의 이력은 건수 0, 평균·표준편차는 빈 값입니다. 점수 계산에 성공한 거래를 기록한 뒤, 다음 거래부터 이전 이력으로 사용합니다. 같은 시각이면 서버가 처리한 순서를 따릅니다. 예를 들어 같은 카드에 금액 10과 30을 넣은 뒤 100을 보내면 세 번째 거래의 직전 7일 건수는 2, 평균은 20입니다.

일일 상위 20건은 하루 거래를 모아 정렬한 평가 기준입니다. API 응답은 모델 파일에서 읽은 고정 점수 기준으로 조사 여부를 결정합니다. 최종 사기 여부는 담당자가 검토합니다.

## 실패와 재시도

- 잘못된 날짜·금액, 빈 ID, 추가 입력 필드는 422를 반환합니다.
- 같은 거래 ID와 같은 내용은 처음 응답을 돌려줍니다. 같은 ID로 내용을 바꾸면 409를 반환합니다.
- 같은 카드의 더 이른 거래가 나중에 들어오면 409를 반환합니다.
- 모델 점수 계산이 실패하면 503을 반환하고 해당 거래를 이력에 반영하지 않습니다. 같은 거래로 다시 시도할 수 있습니다.

`DATABASE_URL`과 `REDIS_URL`이 없으면 상태는 한 서버 프로세스의 메모리에 있습니다. 서버를 다시 시작하면 초기화됩니다. PostgreSQL 모드에서는 거래와 최초 응답이 남아 재시작 후에도 이어서 처리할 수 있습니다. DB 잠금으로 여러 프로세스의 동일 거래·카드 처리를 순서화합니다. `REDIS_URL`도 설정하면 [Redis 상태 공유와 복구](redis_history.md)를 사용합니다. Redis 장애 시 DB로 계산을 이어가며, DB 장애는 503을 반환합니다.

## 검증 결과

교육용 CSV 998건을 순서대로 API에 넣고 일괄 계산과 비교했습니다. 모든 거래의 이력 건수와 군집이 일치했고, 위험 점수 차이는 `1e-7` 이내였습니다. 평균·표준편차는 모델 입력의 float32 표현과 비교해 상대 오차 `1e-6` 이내인지 확인했습니다. 실제 Uvicorn에서 합성 거래를 보내 200 응답을 받았고, 문서 페이지도 확인했습니다.

자동 테스트 19개에서 기존 기능, 잘못된 입력, 같은 시각의 거래, 다른 카드 이력 분리, 동일 ID 재전송·내용 충돌, 과거 시각 입력, 모델 실패 후 재시도와 동시 중복 요청을 확인했습니다. 모델 실패 시 만료 처리된 이력도 원래 상태로 유지되는지 검증했습니다.
